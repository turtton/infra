# Ruckus ICX7250 ファームウェア更新手順

Ruckus ICX7250スイッチのファームウェアを、旧バージョン（08.0.30n）からUFI形式（08.0.95g以降）へ安全にアップグレードするための手順をまとめる。

---

## 1. 概要

ICX7250において、古い非UFI（Unified FastIron Image）形式から新しいUFI形式へ直接アップグレードすることはできない。中間バージョンである 08.0.80f を経由して段階的に更新する必要がある。

- **現在のバージョン:** SPS08030n (FastIron 08.0.30n)
- **中間ターゲット:** 08.0.80f (非UFI形式)
- **最終ターゲット:** 08.0.95g 以降 (UFI形式)

---

## 2. 前提条件

- **シリアル接続:** コンソールケーブルを用意し、スイッチに直接アクセスできること。
- **TFTPサーバー:** スイッチからIP経由でアクセス可能なTFTPサーバーを用意すること。
- **必要なファイル:**
  - ブートコード（08.0.80f用）: `spz10114.bin` または `mnz10114.bin`（ファームウェア配布パッケージに含まれるファイル名を確認すること）
  - `SPS08080f.bin` / `SPR08080f.bin`: アプリイメージ（非UFI）
  - `SPS08095gufi.bin` / `SPR08095gufi.bin`: UFIイメージ（最終ターゲット。08.0.95g以降を推奨）
- **バックアップ:** 現在の設定のバックアップを必ず取得すること。

---

## 3. 事前バックアップ

作業開始前に、現在の設定と状態を保存する。

```bash
# 設定のバックアップ（表示内容を保存）
show running-config

# ライセンス情報の確認（消失リスクに備えて控える）
show license

# 現在のバージョン・起動パーティションの確認
show version
show flash
```

---

## 4. ステップ1: 08.0.80f (Non-UFI) への更新

まず、UFI移行の準備として 08.0.80f に更新する。

> Note:
> バージョンによってはICX側のTFTPクライアントはオプション拡張（blksize, tsize）に対応していない。そのため使えるTFTPサーバーが限られる。
>
> nixの場合`nix shell nixpkgs#tftp-hpa -c sudo in.tftpd -L -s . -a 0.0.0.0:69`みたいな感じでTFTPサーバーを起動し現在のディレクトリのファイルを公開できる(ポート開放を忘れずに!!)
>
> ネットワークは適当に
> ```bash
> vlan 1
> router-interface ve 1
> interface ve 1
> ip address 192.168.1.1 255.255.255.0
> ```
>
> とかでOK

### 実行手順

| 手順 | コマンド | 備考 |
|---|---|---|
| 1. ブートコード更新 | `copy tftp flash <TFTP_IP> <bootrom>.bin bootrom` | ファイル名はFW配布パッケージを確認 |
| 2. アプリイメージ更新 | `copy tftp flash <TFTP_IP> SPS08080f.bin primary` | L2(SPS)またはL3(SPR)を選択 |
| 3. 書込確認 | `show flash` | Primary のサイズと日付を確認 |
| 4. 設定保存 | `write memory` | 更新内容を確定 |
| 5. 起動パーティション指定 | `boot system flash primary` | Primaryから起動するよう設定 |
| 6. 再起動 | `reload` | 確認プロンプトで `y` を入力 |

### 更新後の確認

起動後、バージョンを確認する。

```bash
# バージョンが 08.0.80f であることを確認
show version
```

> **注意:** PoEモデルの場合、再起動後にPoEファームウェアの自動更新が始まる場合がある。更新完了（LED点滅停止など）まで絶対に電源を切らないこと。

## 5. ステップ2: 08.0.95g+ (UFI) への更新

> ```bash
> vlan 1
> router-interface ve 1
> interface ve 1
> ip address 192.168.1.1 255.255.255.0
> ```
>
> 

08.0.80f 上で正常動作を確認後、最終ターゲットのUFIイメージへ更新する。

### 実行手順

1. **UFIイメージの更新:**
   UFI形式はブートコードを内蔵しているため、1つのファイルコピーで完了する。
   現在使用しているイメージ（SPSまたはSPR）に合わせてファイルを選択すること。
   ```bash
   # SPSの場合
   copy tftp flash <TFTP_IP> SPS08095gufi.bin primary
   
   # SPRの場合
   copy tftp flash <TFTP_IP> SPR08095gufi.bin primary
   ```

2. **書込確認:**
   ```bash
   show flash
   ```

3. **設定保存と再起動:**
   ```bash
   write memory
   boot system flash primary
   reload
   ```

### 最終確認

```bash
# バージョンが 08.0.95g 以降であることを確認
show version

# セカンダリパーティションへの同期（推奨）
# UFI移行後は両パーティションを揃えておくことが望ましい
copy flash flash secondary
show flash
```

---

## 6. UFI (Unified FastIron Image) について

- **従来方式:** ブートコード（bootrom）とアプリケーションイメージ（primary/secondary）を個別にフラッシュへ書き込む必要があった。
- **UFI方式 (08.0.90以降):** 全てのコンポーネントが1つの `.bin` ファイルに統合された。これにより、不整合のリスクが低減され、管理が簡素化されている。
- **移行パス:** 08.0.80f はUFI構造への移行をサポートする最終安定版であり、中間ステップとして不可欠である。

---

## 7. 注意事項

- **推奨バージョン:** 08.0.95a 等の初期リリースにはメモリリークやスタックの不安定性が報告されているため、修正済みの **08.0.95g 以降** を使用すること。
- **コマンド構文の変更:** メジャーバージョンを跨ぐため、一部のコマンド構文が変更される場合がある（例: `port-name` → `port-description`）。
- **SSHの改善:** 08.0.30n ではSSHの暗号化アルゴリズムが古く、現行のSSHクライアントからは接続しづらかったが、更新後は接続性が改善し、回避策が不要になる場合が多い。
- **安定性:** ICX7250においては、09.0.10系や08.0.95a等の初期リリースで不安定性の報告があるため、ホームラボ用途では実績のある **08.0.95g 以降** を推奨する。

---

## 8. 更新後のチェックリスト

| 項目 | 確認コマンド | 期待される状態 |
|---|---|---|
| バージョン確認 | `show version` | 08.0.95g+ |
| パーティション整合 | `show flash` | Primary/Secondary共に更新済み |
| ライセンス保持 | `show license` | 既存ライセンスが有効 |
| SSH接続 | - | 回避策なしでログイン可能 |
| ポート状態 | `show interface brief` | リンクアップ状態が正常 |
